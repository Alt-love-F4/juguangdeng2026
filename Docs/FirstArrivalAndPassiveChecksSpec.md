## 5. 自动检定规则与副文本

### 5.1 计算和展示分工

NCS 到达节点时读取现有玩家属性，只计算一次；阈值比较、分支选择和 UI 共用同一个结果快照。UI 不再次计算属性，不执行 NCS Result。

随机只用于提示词选择，绝不改变属性、门槛、成功率或剧情。提示抽词使用独立的表现随机源，不消耗经营／叙事逻辑的随机序列。

### 5.2 展示规则

成功示例：

```text
知觉 ≥ 3 · 已察觉
```

- 提示挂在成功分支第一条实际正文的第一个对话框／分页右下角，与该正文一起出现。
- 首框内一直可见，玩家正常推进后清除；同条正文后续分页、后续台词和下一段剧情不重复显示。
- 提示不占正文行、不挤掉正文、不额外要求确认，也不增加推进次数。
- 不显示“判定成功”“检定成功”“触发隐藏剧情”或完整实际值算式。
- 未通过时只播放相应剧情，不显示“未察觉”“失败”或灰色占位提示。
- 未参与检定的普通对话默认没有副文本；复用 Panel 时清空残留。
- 快进必须执行自动检定并走正确分支；遇到剧情选择仍按现有规则停下，不能代选。

当前两个节点均为单属性知觉检定。已有多条件 AND／OR 判定能力保留，本轮不将多条件结果压成一句可能误导的单属性提示。

### 5.3 提示词库

按稳定属性 ID 分类，第一版等概率抽取非空候选词。推荐做成独立的表现配置 ScriptableObject，由 DialoguePanel 或展示适配器引用；词条集中编辑，不写入剧情正文或判定代码。

| 属性 ID | 显示属性 | 初版候选词 |
| --- | --- | --- |
| perception | 知觉 | 已察觉、捕捉到细节、觉出端倪 |
| wisdom | 智慧 | 若有所悟、理清头绪、看出门道 |
| language | 语言 | 一语中的、说到点上、言有所中 |
| courage | 勇气 | 鼓起勇气、毫不退缩、稳住心神 |

本轮两个实际检定使用知觉词库，其他三类只是准备可编辑词条，不新增剧情检定。每个节点可通过表现配置指定固定词；未指定时才随机抽取。

同一次检定的提示词首次抽出后固定。Panel 刷新、重开、分页或恢复同一次演出均不重新抽词。可保存词条 ID 或等价的表现快照；不为提示词新增全局剧情 Flag。词库缺失／没有有效候选时记录配置诊断并使用“有所领会”，不影响真实判定与分支。

### 5.4 TMP 样式和可编辑性

当前 DialoguePanel Prefab 正文为棕色；初版副文本统一采用深青绿色 `#147D78`，透明度 1，用颜色与正文区分。此颜色是初始方案，交付时需结合真实对话底图检查可读性。

- 使用独立 `TextMeshProUGUI`，放在现有 DialoguePanel 内。
- 初版参考字号为正文的 65%（正文 32 时约 21）；右对齐，距对话框右、下边各约 24 个参考分辨率单位，并避让继续按钮、操作提示、选项和正文。
- 用 Prefab 上 TMP 的 `color` 字段设置颜色；字体、字号、颜色、对齐、锚点和边距可直接在 Inspector 修改。
- 颜色标签不写入配表正文，运行时展示不强制覆盖美术调整的 TMP 颜色。
- 这一轮四类属性共用该颜色。若真实底图上看不清，工程可调整初始色或增加轻描边，并报告实际值；以清晰可读为验收目标。
