# 对话阅读体验与 GM 叙事调试 Spec

日期：2026-10-15  
状态：讨论结果整理；交给工程 Agent 评审与拆分施工。本轮只产出文档，未实现、未做 Unity 运行验收。  
目标读者：演出、NCS、GameFlow 工程负责人。

## 1. 目标与交付范围

让策划能舒服地阅读、回看、定位和反复测试一小段剧情，再用同一套规则接入后续文案。

本次有两个必须交付的部分，建议顺序实施、分别验收：

- A：立绘稳定、鼠标滚轮推进、纯文字历史记录。
- B：现有 `~` GM 左侧新增「叙事调试」，支持查找、演出预览、定位重播、分支测试和结果诊断。

不以「文字已经配进表」「按钮已经出现」「只有硬编码演示能跑」作为完成标准。A 必须覆盖正式 NCS 对话；B 必须能读取当前生成配置并测试真实配置中的分支。

## 2. 已确定的产品规则

### 2.1 立绘

同一角色继续说话，保持原位置、大小、朝向和当前表情，不重复退场、入场。文案明确写了表情差分才换表情；明确写了动作、CG、镜头、震屏等效果才执行对应演出。

说话人切换不等于人物入场。换表情不等于换人。没有写新的表情时保留当前表情，不自动恢复默认脸。

### 2.2 阅读

- 鼠标滚轮向下、左键点击现有正文推进区、空格、Enter：先补全当前页文字，再翻页或进入下一句。
- 鼠标滚轮向上：打开历史记录。
- 对话框增加清晰的「历史」按钮。
- 历史只回看，不回滚剧情，不重新选择分支。
- 第一版历史只显示角色名和文字，不放角色头像。
- 历史保留已经显示的台词、旁白和玩家实际选择；不显示未读正文或未走分支。
- 第一版历史仅属于当前游戏会话，不写入游戏存档。读取存档后从实际重新播放的内容开始记录。

### 2.3 GM

沿用现有 `~` GM 和左侧分类，增加「叙事调试」。重播、跳分支和测试条件放在这里，不加入玩家历史记录。

### 2.4 后续内容配置的地图约束

本段记录产品方向，供后续配文案 Spec 引用，不属于本次地图施工：

- 必过剧情不消耗行动点，不列入事项面板。
- 玩家尝试结束当天时，如仍有必过剧情未完成，阻止结束并聚焦、高亮其所在地点，引导玩家完成。
- 消耗行动点的可选活动通过地图地点、行动详情参与；事项面板只承载这类活动的相关事项。
- 必过剧情与可选活动可以同时开放，不因主线未完成而默认锁死其他地点。
- 哪个事件拦截哪个出口、同日多个必过事件如何排序，以及咖啡馆内如何返回地图，留给后续地图与日程 Spec 明确；本文件不推定「进入咖啡馆前必须清空主线」。

## 4. A：立绘连续性

### 4.1 状态判定

角色身份以稳定 CharacterKey / NCS 角色 ID 判断。不能用新建的 C# 对象引用、显示名或 Sprite 是否相同来判定换人；同一角色的两个表情仍是同一个人，不同角色复用剪影仍是不同角色。

| 本句与当前舞台的关系 | 行为 |
| --- | --- |
| 同一角色、没有新指令 | 保持当前立绘，不启动入退场，不重置位置与缩放 |
| 同一角色、明确指定新表情 | 原位更新差分，不退场、不入场；锚点、比例和基线稳定 |
| 说话人换到已在场的另一角色 | 更新姓名和说话高亮；原位保持所有角色 |
| 旁白、无人说话 | 保留舞台；按现有设计取消说话高亮 |
| 空角色位首次放入角色 | 沿用已有默认首次入场效果 |
| 某角色位实际换成不同角色 | 沿用已有替换效果，不把每句发言都当作替换 |
| 明确退场、换位、重新入场、震屏或 CG 指令 | 通过现有演出接口执行；明确指令优先 |

没有 CharacterKey 的旧预览数据要有确定的兼容策略并补充诊断，不通过显示名猜测身份；正式 NCS 数据必须提供稳定角色 ID。

### 4.2 连续剧情与布局

- 左、中、右角色位都遵守上述规则；保留双人、三人布局和不镜像约定。
- 同一说话人连续多句，连说话聚焦动效也不得每句从原始比例重启；聚焦状态不变时保持当前状态。
- 表情差分不得因原图尺寸不同而让人物忽大忽小或脚底基线跳动；优先沿用现有角色表现资源的统一锚点和缩放。
- 同一场景内，仅因对话分页、NCS 段落切分、属性检定分支或连续选项而换了播放快照，不应重新播放整个面板及全体人物入场。
- 保持舞台必须有明确的连续播放归属。新事件、新场景或独立预览开始时，以其初始舞台为准；不能把上次人物无条件带进下一段。
- 检查适配器的初始角色设置，避免把脚本后面才出场的人物提前放到第一句。
- 真正 Stop、取消、换场景、退出测试或销毁时，清理旧动画、协程、音频 owner、回调和舞台状态。

### 4.3 文案转换规则

默认「没写就保持」。导入器/适配器必须区分未指定表情与明确指定默认表情，不得因每句缺省值而强行恢复默认脸。

表现字段仍使用既有 NCS 字段及效果资源。当前字段无法表达的演出要求，列出原文、缺少的能力和建议；先作为独立差异说明，不静默发明一套平行字段。

## 5. A：滚轮与输入

### 5.1 推进语义

输入优先级为：GM / 其他顶层弹窗 > 历史 > 选项 > 当前对话。被上层消费的输入不传到下层，不传到地图、咖啡馆或背后的按钮。

- 当前页未揭完：一次推进只补全文字。
- 当前页已揭完但本句还有下一页：一次推进只翻一页。
- 当前句已完整显示：一次推进只进入下一句，或显示本句后续选项。
- 选项显示时，滚轮不得代替选择，不得自动选中、略过或结算选项。
- 原有入退场和阻塞效果期间的推进限制保留，避免误触跳过演出。

### 5.2 滚轮处理

- 向下为推进，向上为历史入口。只有对话拥有输入焦点且没有更高优先级界面时才响应。
- 实现应兼容普通滚轮和连续滚动设备：小增量累积到阈值、一次滚动手势只发出一次命令、适当去抖；阈值/间隔可配置。
- 同一帧多种输入合并为一次推进；打开和关闭历史、GM 的那次输入不能顺带翻句。
- 打开历史时清空本次滚轮推进累积，关闭时也不重放剩余滚动量。
- 历史、选项列表、GM 内的滚动交给各自滚动区域。选项存在时仍可点击「历史」查看记录，关闭后回到原选项。
- 不把整个屏幕上所有按钮的左键都解释为推进；沿用正文/现有空白推进区，按钮点击单独消费。

## 6. A：纯文字历史记录

### 6.1 展示与入口

使用正式对话 UI 的受控子视图或既有 UIKit 管理方式，不另建独立测试 Canvas。

- 点击「历史」或对话时滚轮向上打开；初始定位到最新记录底部，之后正常滚动查看更早内容。
- 台词显示角色名和正文；旁白可标「旁白」；选择显示 `玩家选择：「实际选择的文字」`。
- 不放头像、工程 ID、textKey、测试按钮或剧情回滚按钮。
- 提供可见关闭按钮；Esc 优先关闭历史，该次 Esc 不取消对话或打开暂停菜单。
- 历史滚动区能容纳长文本，保留换行，不能裁掉段尾；文字使用已解析的玩家姓名，不暴露原始 key。
- 无记录时显示明确空状态。

### 6.2 记录规则

- 记录已显示内容，不根据配置提前枚举未来台词。
- 打字未完成时打开历史，只允许看到已经揭出的部分；长句已读分页可合成一条记录，不能提前显示后续页。
- 补字、同句翻页、打开/关闭历史不得生成重复记录。
- 只记录成功提交的实际选项一次；不能记录其他选项、被拒绝点击的灰色选项或未走分支。
- 同一句真实发生第二次可以再次记录。去重依据是播放实例和行身份，不是全文字符串。
- 历史跨同一正式会话的对话 Panel 关闭/重开保留；开始新游戏、返回主菜单、读取其他存档时清空。
- 使用独立记录服务/会话数据承载，不依赖可缓存 Panel 的局部列表；预览历史和正式历史隔离。
- 第一版内存上限默认 500 条完整条目，可配置；超出从最早完整条目淘汰，不截断当前条目。此项是工程默认值，后续可调。

### 6.3 暂停与恢复

打开历史时，暂停当前阅读的打字、自动翻页/已有 SKIP、选项输入、语音以及本次对话拥有的效果计时；不推进当前事件或调用完成回调。

关闭后保持原行、原页、已显示字数、舞台、选项和事件状态；可继续打字和语音，SKIP 保持关闭，避免刚退出就连跳。不得通过重新 Play 当前事件实现关闭历史。

暂停应有可嵌套的 owner/令牌或等价机制，避免历史关闭时解除 GM/暂停菜单仍持有的暂停。仅阻止输入不足以暂停非缩放时间的 Tween、协程和计时器；验收必须覆盖这些情况。

历史本身不修改 Time.timeScale；timeScale=0 时仍可打开、滚动和关闭。

## 7. B：GM「叙事调试」界面

### 7.1 入口与页面

通过现有 `FreeCafeGMPanel.RegisterCategory` 或等价扩展注册，不新建 GM 窗口。无论是否加载 CoffeeShop，都能使用查找、诊断和共享场景预览入口；不能被 AddAction 的默认经营系统检查挡住。

页面由「内容查找」「播放控制」「测试条件」「状态与诊断」组成，优先复用现有控件。大列表使用滚动/虚拟化或分页，文本可选中或复制，避免几十个无筛选按钮堆满页面。

### 7.2 内容查找

- 覆盖当前配置中的 Event，以及 OpeningPresentation、Conversation 等演出入口。
- 用中文标题、事件 ID、presentationKey / presentationId、正文关键词搜索。
- 区分事件与演出类型，显示关联关系；同一演出被多个事件复用时不能假装只有一个事件。
- 搜索使用当前配置和同一文本解析服务。正式会话不可用时可加载生成数据并使用预览姓名，不启动正式新游戏。
- 定位至少包含来源类型、eventId（如有）、演出 key、源行 ID / seq、当前页。临时快照行索引与源行 ID 必须区分。
- 配置重载后保留仍有效的选择；已删除 ID 显示失效原因，不偷偷切成其他事件。

### 7.3 只看演出模式

用于看文字、立绘、布局、CG 和效果，不验证触发和结果。

必须支持：从头播放、停止、重播本段、上一句/下一句、定位指定句、到下一组选项、调整预览文字速度、逐字开关。

- 上一句、定位指定句属于 GM 演出定位，不是正式 NCS 回滚。
- 定位时重建到目标句所需的舞台状态：人物、表情、位置、背景、镜头、持续遮罩和音乐等；不能只改 LineIndex。
- 跳过的中间句不逐个播入场、不把一次性音效快速叠播；只重建目标画面，目标句的明确效果正常执行。
- 到下一组选项不得自动选择。纯演出选择可以沿配置预览后续表现，但不执行 Result、结局、DayFlow 或玩法操作；缺少分支上下文时明确提示使用「分支测试」。
- 允许指定一个演出直接试看，即使正式事件条件未满足；页面持续显示「只看演出，不结算」。
- 一个事件包含多个演出段落时，「重播本段」只重复所选演出段落；「重测事件」从事件测试起点开始，两者按钮不能混淆。

### 7.4 分支测试模式

复用真实 NarrativeController 的条件、检定、选项、事件队列和结果语义，在独立内存测试会话中运行，不用硬编码模拟成功台词。

第一版必须支持：

- 设置测试日期/地点、四项属性、配置中已有进度条和布尔条件。
- 查看事件发生记录；准备测试所需的前置事件事实，不结算其奖励。依赖事实必须引用已有 ID，不凭空伪造未知 ID。
- 同时显示「当前值、门槛、是否满足」；例如知觉 2 / 3，比较后走真实失败 / 成功分支。
- 设置条件后显式「建立测试起点」，再请求事件。修改另一轮测试条件时，先恢复原起点，再修改条件并建立新起点，不能把上一轮奖励和事件记录带入新起点。
- 测试结束显示选项、检定和结果差异；可「恢复测试起点并重测」走另一分支。
- 正常选择仍走实际条件校验，不让 GM 勾一个成功开关冒充真实检定。
- 日期/阈值触发测试显式使用现有调度入口：显示触发前值、修改后值和提交动作。直接请求事件与验证自然触发分开，不能用 QueueEvent 成功证明日期/阈值已经接通。

测试起点包括测试使用的 NCS 状态、动作/物品状态和外部属性/资金等内存 Provider。每次重测深复制恢复，禁止共享可变字典；不能只恢复 Bar 而遗留已发生事件、选项记录、队列或金钱。

结果处理分为：NCS 内部状态按真实逻辑更新；资金/外部数值通过内存测试 Provider 更新；场景切换、顾客实例、正式成就等实际宿主副作用由测试适配器拦截并报告。明确区分「已验证数值结果」「仅记录宿主请求」「缺少依赖未验证」。必要宿主依赖不支持时，该项显示不可测试及原因，不能默认成功。

日期设置不得推进正式日程；测试「结束回合」不得变成正式「结束当天」。未知或不支持的效果要明确报错，不静默忽略。

### 7.5 状态与报错定位

页面至少显示：

- 正式只读 / 演出预览 / 分支测试模式，以及当前测试起点。
- 当前事件、演出、源行和页；当前选择、检定快照、待播事件及活动演出状态。
- 条件不满足项及当前值/要求；事件不存在、已发生一次、被锁定、数值未就绪、系统忙等拒绝原因。
- 结果的旧值、新值及宿主请求；未知资源、缺失文本和无效效果的来源定位。

诊断应扩展/复用运行时的只读解释接口；不能在 GM 复制一份可能与实际执行不一致的条件算法。无副作用检查不得通过真实 QueueEvent 试探，也不能读取一次检定后改变其缓存或随机状态。

提供「复制定位信息」，纯文本至少含模式、eventId、演出 key、源行 ID / seq、页、属性/前置摘要、最近一次结果或错误。截图为可选后续能力，不是本次依赖。

## 8. B：正式会话、预览与生命周期

### 8.1 上下文隔离

只有一个演出上下文可以拥有可交互舞台。GM 打开时，其输入和暂停优先于对话；关闭 GM 后，不将点击、滚轮、Enter 传给底层。

- 正式会话中随时可查看当前定位、诊断和复制信息。
- 第一版完整重播、跳句、改测试条件在独立测试上下文内进行。共享 PresentationDebugScene 是主要测试入口。
- 正式演出仍活动、队列未排空或事务未完成时，启动测试的操作明确显示「请先结束当前正式演出；或在共享调试场景测试」。保留选中的测试目标，不静默取消正式剧情。
- 正式会话到达安全边界后，可以启动独立测试；测试期间暂停正式日程、经营计时和输入，测试退出恢复进入前的状态，不执行测试完成导致的正式流程回调。
- 从共享场景可直接加载当前生成配置开始测试，无需先走序章、角色创建或开场教程。

本次不承诺在任意正式剧情中途无缝回滚、重选再恢复。活动剧情内任意时刻热切换属于后续能力，不能通过强行 Stop / Reset 正式 Runtime 来伪装实现。

### 8.2 禁止污染正式状态

- 预览不使用正式事件的完成回调，不结算正式 Result，不修改正式历史、玩家资料、行动点、库存、资金、条件或日期。
- 分支测试复用 NCS 核心，但有独立状态与 Provider；不能替换 NarrativeRuntime.Instance 或重置正式会话来运行测试。
- 不采用「先改正式状态，退出再回滚」作为隔离办法；外部回调/成就/保存未必可以回滚。
- 预览/测试的保存、自动存档和正式成就入口均不接入；原正式存档格式不新增调试字段。
- 停止、重测、关闭测试、换场景时，取消测试协程、效果、音频、订阅和旧回调。旧完成回调不能在新一轮测试中到达。
- GM 分类注册幂等，场景切换、Domain Reload 和重复进入 Play Mode 后不重复添加。
- GM 关闭仅恢复所属暂停；「停止预览」和「退出测试会话」语义清楚，后者释放测试资源并恢复原上下文。

## 9. 数据与模块责任

建议使用下列职责划分；类名可遵循项目现有习惯，不强制另建大型框架。

| 职责 | 负责内容 | 不负责内容 |
| --- | --- | --- |
| 对话表现状态 | 角色连续性、舞台差异、页/字数、暂停恢复 | 事件条件和结算 |
| 历史会话数据 | 已读文字、已提交选择、会话清理 | 读取未走分支、恢复 NCS 状态 |
| GM 页面 | 查找、控件、来源定位、复制信息 | 自己计算一套分支规则 |
| 叙事调试会话 | 预览快照、测试起点、独立核心状态、测试 Provider | 正式存档与 DayFlow 推进 |
| NCS 只读诊断 | 与实际判定一致的原因和数值说明 | 为了诊断触发事件或修改状态 |

复用现有文本解析、角色资源解析和 NCS 演出适配。Opening 与 Conversation 两条入口都要覆盖；不能只修某条临时预览路径。

来源定位随演出快照传递或维护独立只读映射，玩家 UI 不显示工程元数据。不要靠台词字符串反查唯一行，也不要把 Excel 行号与生成数据索引混用。

本次默认不改 Excel schema。确需增加不可替代的元数据时，先在交付中说明用途和兼容策略；沿既有 schema 扩展，不新增剧情字段标准。修改源表/schema 后执行 `Assets/ConfigTables/GenerateAll.bat`，确认成功并通过现有业务校验，不直接编辑生成 JSON/C#。

## 11. 明确不在本次施工范围

- 历史头像、点历史回滚、正式游戏任意分支重选。
- 新的前端 Excel 编辑工具、文案自动批量导入、批量改写正文。
- 全量故事配表、地图必过剧情拦截、事项面板重构、每日阶段重排。
- 黑屏 OpeningProloguePanel、阅读/信件/视频面板的整套交互改版。
- 新做自动阅读、已读标记及跨存档「只跳已读」系统、隐藏界面和整套按键自定义。这些属于已讨论的体验方向，后续单独细化，不因本文件自动进入本次范围。
- 任意运行中热重载 schema 或生成 C#。GM 可在无活动测试时重载已生成且验证有效的数据；Excel/Luban 生成继续走既有编辑器流程。

现有 SKIP 和音频能力应保持可用，并接入历史/GM 的暂停与输入互斥；本次不顺带改其玩家产品语义。

## 12. 实施顺序与交付要求

建议按以下三个检查点推进，每个检查点有能重复运行的验收样例：

1. 修稳定立绘与连续段落，再完成滚轮、历史和输入互斥；先验收 A，不让 GM 掩盖正式对话缺陷。
2. 增加 GM 查找、定位、演出预览、重播和复制信息；在共享场景无需走开场即可使用。
3. 接入独立测试起点、真实分支/结果测试和原因诊断，再验收正式会话隔离。

工程交付必须附：改动文件、如何打开使用、共享场景的具体入口、真实配置验证对象、实际执行并通过的测试、未实现/未验证项及原因。提供能让策划照做的短步骤，不只给类名。

示例使用流程应最终能做到：

```text
打开共享 PresentationDebugScene → Play → ~ → 叙事调试
→ 搜索「初来乍到」或对应事件 ID → 只看演出 → 定位并重播问题句
→ 切换分支测试 → 准备知觉2 → 建立测试起点 → 播放真实检定
→ 恢复测试起点 → 修改为知觉3并建立新起点 → 重测成功路径
→ 复制问题定位 → 发给工程 Agent
```

若检查点未完成，明确标为部分交付，不能把入口已接通当作整份 Spec 已完成。
