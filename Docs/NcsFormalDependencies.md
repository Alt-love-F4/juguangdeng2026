这份文档把项目里原先使用的 `B-*`、`C-*`、`D-*` 施工编号翻译成可以直接执行的工程任务。它不是新的剧情设定，也不替代原稿；它只记录一段已有文案要进入正式游戏流程时，当前还缺什么。

## 1. 先看结论

当前项目的 NCS 配置已经能承载多种正式入口：地图行动、早晨地图前、营业后、夜晚前，以及事件之间的安全续接。当前 38 个事件的 Unity 扫描报告为 `Errors=0`、`Warnings=0`；9 个正文根事件都已经有正式入口和根完成结果。剩下的是实机流程回归，以及 2 个没有权威数值来源的页面条件：它们现在会安全跳过页面，不会让整段剧情崩溃，也不会伪造完成事实。

1. **入口**：玩家在什么动作或日期阶段看到这段内容。
2. **前置事实**：前一段剧情是否真的完整结束，而不是只打开过或看过某一页。
3. **中途玩法回接**：经营、制作、检定、读信或选择结束后，是否回到原剧情的正确页。
4. **最终结算**：只在整段剧情完成时写入 `completed`、关系、倾向或其他结果；取消和中断不能误结算。

缺少其中任何一项，都可能出现“台词能播，但下一段永远不解锁”“取消后剧情被判完成”“读档后重复结算”等问题。

## 4. 本轮自主决策规则

为了不让工程因为每个小问题停下来，本轮采用以下规则：

1. 已有明确入口、条件、演出和结果的事件，直接接入并测试。
2. 缺少美术但不影响逻辑的，使用现有可替换占位，保留稳定 key，不复制其他角色身份。
3. 缺少数值、关系来源、金额、正式结果语义的，不猜数值、不默认成功、不写入正式结果。页面级未知依赖可以安全返回 false 以隐藏该页，但必须保留警告，不能把它当成“条件已满足”。
4. 选项和检定只在同一根剧情完成时提交正式事实；取消、切场景、读档中断不提交。
5. 缺少完整原稿的内容只做隔离预览，不建立正式完成标记。
6. 不恢复已经删除的 `npc_a`、`npc_b`、`npc_c`、`npc_d` 测试剧情，也不删除革命正文。
