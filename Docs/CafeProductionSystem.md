# 咖啡馆制作系统：实现与扩展说明

## 来源与范围

依据 `策划文件/策划/玩法/咖啡馆玩法(1).xlsx` 的「制作界面」sheet：订单/杯具/研磨/出餐/原料（B8:E41）、滴滤与加热（C43:G70）、小料与返回（B71:B72）、质量评价（B77:C92）、咖啡谱（B95:D107）。本次不修改 Excel 或 Luban/NCS 表结构。

仅在现有 `Assets/Scenes/CoffeeShop.unity` 的 Counter 区域重构制作布局、镜头与操作栏；仍从营业区入口进入。其他楼层、实体 ID、实体 Prefab、世界存档参与者及 DayFlow 经营端点保持原设计。没有新建制作 Scene、工作台插槽或按订单锁定步骤的系统。

## 操作流程

1. 从右侧箭头或「一楼出餐台」进入制作区；可以先备料再开店。
2. 点击小杯/大杯堆，或底栏「小杯/大杯」选择出餐托盘上的杯子。默认小杯 240 ml、大杯 400 ml。空杯可换型，原空杯归还来源库存；已有任何内容就不能换杯。
3. 咖啡豆拖到研磨器，点击启动 12 秒自动研磨；后续有效点击快进 1 秒（有 0.12 秒点击间隔）。拖出成品抽屉到咖啡壶。
4. 清水/牛奶/可可粉拖到加热壶，点击启动：4 秒加热 → 5 秒沸腾 → 10 秒温热 → 常温。常温/温热壶可再次点击加热。长 Tick 正确消耗跨阶段的剩余时间。
5. 把热水壶拖到咖啡壶上方，**向下拖动倾倒，向上抬起回正，松手停止并归位**。第一滴水进入后开始计时。默认完美 7.5 秒、200 ml；绿/金区范围均可配置。
6. 注水不足时可继续；在建议量范围内停止时得到咖啡原液。过量需清空重做。咖啡壶与加热壶均可拖到出餐杯上方按实际毫升数倾倒。
7. 可以倒到地上，杯满后的溢出也计入洒漏；不返还资源。壶本身保留同一实体身份，松手回到工位。
8. 蜂蜜、奶油、方糖从来源拖到出餐杯。原则上先咖啡，再其他液体，最后小料；方糖可随时加。
9. 左右翻页决定本次交付哪个订单；点击「出品」交付当前显示的订单。空杯、半成品也允许出品，但质量低。
10. 不满意可按配置重做；本次杯和资源消耗，原订单/顾客保留。满意后订单移除并结算收入，同时显示完成反馈；重复出品不会重复结算。
11. 「丢弃杯」丢掉杯和内容物、不退款。选中设备后「清空选中设备」或右键设备丢弃内容物。
12. 「返回入口」回到此次进入制作区之前的区域，设备和杯状态不重置。咖啡谱只浏览已经学会的餐品，可翻页查看图标、风味和制作说明。

原场景还有一个独立 `Canvas/Image` 默认 100×100 白方块，曾遮住加热壶并拦截世界鼠标输入。构建器仅禁用符合该特征的空 Image，并关闭它的 raycast；保留原对象，不删除整个 Canvas。

## 数据与职责

- `CafeWorld` 仍是唯一权威模拟层；`WorldEntity.id`、`contents`、`quality` 等既有设计保留。
- `ProductionEntityState` 保存道具阶段、计时、萃取统计、加入顺序、洒漏。`Portion` 增加毫升、加入时温度、制作质量和顺序；**没有第二份流体库存**。
- `ProductionSession` 只保存制作模式、托盘杯、返回区域、小游戏令牌和最后评价；不存 Unity 引用。
- `FreeCafeRuntime` 负责指针、倾斜、落点、相机区域与视图同步，不代替世界扣库存。
- `FreeEntityView` 显示物品状态、毫升条、拖拽拒绝/返回及基础加工反馈；仍使用已有 Prefab 和美术库。
- `FreeCafeProductionHud` 复用现有 `FreeCafeHUD` Canvas，制作区内切换操作栏，其他区域恢复原 HUD。
- 制作相机近景保存在 Counter 的 `CafeAreaAnchor.orthographicSize`；返回其他区域恢复原相机尺度，不裁切 camera.rect，不影响射线输入。

## 配置与评分

配置入口是 `Assets/Resources/FreeCafe/catalog.json` 的 `production`、`entities.capacityMl` 和 `products`。

策划没有明确给出的容量、配方毫升、甜度、档位边界、满意阈值和重做次数采用**原型默认值**，不当作最终策划数值：

- 萃取：完美时间 7.5 s；金区半径 1 s，金区外再延伸 3 s 为绿区。完美水量 200 ml；金区半径 15 ml，再延伸 35 ml 为绿区。
- `extractionScore`：时间偏差、水量偏差、流量均匀度三项平均，0～100。停顿通过有效倾倒时间/总萃取时间降低均匀度。
- 出品五项：萃取质量、加液量/加入时温度、加入顺序、甜度、浓度，等权平均，0～100。
- 材料完整度另作倍率；错误杯型乘 0.75，每条额外非配方原料记录乘 0.8，防止空杯/半成品获得虚假高分。
- 温度相差一档扣 35 个温度子分；咖啡晚于其他液体扣 20 个顺序子分，小料早于液体扣 15。
- 蜂蜜每份计 2 个甜度单位，方糖每份计 1 个单位；浓度是最终咖啡原液占液体体积的比例。
- 五档：0～20 难以下咽；20～40 差强人意；40～60 平淡普通；60～80 醇香可口；80～100 匠心佳作。
- 默认满意阈值 60，最多重做 1 次，均按餐品配置。后续可以将顾客习惯移到订单/NPC 配置，不需要改 Panel。
- 原有店员/金钱/技能设备加速沿用同一耗时倍率；自动加工在装料后启动，自动交付只判断当前托盘杯的制作评分，不拿别处的杯子。

## 流体与道具表现扩展

本轮实现的是**体积守恒的基础倾倒交互**，不是 Navier–Stokes、粒子或容器内部真实 2D 物理流体。壶倾斜量决定出水速率，目标/容积决定接收和洒漏；内部表现目前是状态美术和容量条。

将实现 `ICafeLiquidPresenter` 的 MonoBehaviour 挂到实体，赋给 `FreeEntityView.liquidPresenter`：

```csharp
void Present(CafeLiquidSnapshot snapshot, float tilt, bool pouring);
```

真实流体、材质、液面、壶盖/抽屉动画可以消费快照和倾斜量，但不能自己扣第二份库存。需要扩展多种道具状态时，在 `ProductionEntityState`/实体配置增加可序列化数据，再由表现组件消费，不把状态藏在 Animator 或 GameObject 内。

两个额外加热壶位置目前为**升级预留标识**，不是无偿可用设备。已有 `CafeWorld.AddMachine("machine.heater")` 仍负责招募/金币/设备数校验，新设备有自己的内容物和计时；不同壶的独立热状态已测试。购买 UI、升级工位绑定及各壶专属配色/动画留给后续需求。

## 小游戏扩展

点击「拉花入口」按钮或场景中的拉花杯，检查出餐杯已有咖啡和牛奶，然后创建杯 ID + 唯一启动令牌。

- 未注入模块时显示明确的占位说明，只有取消入口；不会自动宣布拉花成功。
- `production.requireLatteArt` 默认 false，因此尚未实现小游戏不会阻断基础拿铁交付。真实玩法就绪后可改 true。
- 在 `FreeCafeMiniGameGateway.presenter` 注入实现 `ICafeMiniGamePresenter` 的 MonoBehaviour：

```csharp
void Begin(string kind, string cupId, string token,
    Action<string, bool, float> complete);
void Cancel(string token);
```

完成时在 Unity 主线程回传同一个 token、是否完成和 0～100 分数，模型通过 `ResolveProductionMiniGame` 校验。成功分数 ≥75 才标记完成拉花。重复/过期令牌、杯子被更换/丢弃、界面停用和读档前的旧回调都不能修改新杯。小游戏进行时禁止加料/出品；取消保持原料。退出/读档由 gateway 的 owner 取消展示器和回调。

## 存档兼容

现有世界存档参与者 ID 不变。制作模式使用 v3 快照；仍可读取 v1/v2。

进入制作模式时：旧设备任务取消，但原料/已有产物实体 ID 与品质保留，并安全放回设备旁；旧杯没有毫升信息，按旧份数容量映射到新容量，保留装填比例和液体组成，不制造超容量坏档；补入旧档没有的清水、方糖和拉花入口，不复制已有来源。

恢复先校验毫升/温度/阶段/质量/引用及容量，全部通过才替换正在运行的世界。NaN、Infinity、错误阶段、悬空托盘杯和过期小游戏引用均拒绝。已加入杯中的温度记录的是加入时状态，符合 sheet 的评分时点，不在杯内另做冷却模拟。

## 构建与回归

手动回归菜单：`Tools > Free Cafe > Verification > Run EditMode Tests / Run PlayMode Tests`。验证器只响应菜单操作，没有启动轮询或后台命令文件监听。

更新同一场景的菜单：`Tools > Free Cafe > Rebuild Production Interface`。当前场景有未保存修改时会明确拒绝，不覆盖用户的未保存内容；构建前备份到 `output/production-validation/`。重建只更新自己的制作 UI、Counter 预览、制作区标识和 Counter 镜头。

- EditMode：`FreeCafeProductionTests` 覆盖杯型、事务性拖放、研磨/热阶段、并行壶、注水、守恒/溢出、质量、重做、令牌、迁移/读档与返回。
- PlayMode：`FreeCafeProductionPlayModeTests` 加载现有 CoffeeShop，覆盖原 Canvas 复用、真实拖放/壶倾倒、按钮与小游戏占位。
- 原自由操作测试显式使用旧模式，继续覆盖既有身份、跨区域移动、存档和真实鼠标输入；旧测试的过时售价/时长/补货硬编码改为读取当前配置，不放宽行为断言。
- 未接入 NCS 结算、没有更换 DayFlow 端点，也没有新建演出调试 Scene。
