### 3.3 资格、待播放与实际播放

至少区分：未满足、已满足但等待入口、正在播放、已完成。地图行动还区分未看过与已看过。状态可由现有数据组合表示，不要求照抄这些命名新增类。

- 数值变化和日期检查先决定资格。等待晚间/地图入口的资格，不加入当前立即播放队列，不抢走当前 UI。
- 待入口的内容不使全局 `IsBusy` / `IsSafeBoundary` 永久阻塞。阶段能进入、其他行动能执行；待播放列表不是正在演出。
- Cross 触发：记录实际跨阈值产生的资格；数值后来下降不撤销这次已发生的跨阈值。沿既有 reachCount / onceType 语义，保存触发来源和计数，不能重算出一次新跨越。
- Hold 触发：在允许的入口重新检查当前是否仍满足保持条件；不满足时本次不播、不标完成，之后仍可重新符合。Hold 不因为某次达标就自动永久锁定资格。
- 日期：仅在匹配日期/重复规则和匹配阶段收集；S2 只在 day=2 的 BeforeNight 开放，不能提前到早间，也不顺延到另一天补播。
- 开始前统一重查事件锁、已完成、其他前置条件。资格成立不绕过这些限制；跨阈值事实不因数值回落抹除，但独立前置失效仍可阻止开始。
- 同一入口同一批允许开始的事件，优先级降序；同优先级按现有配置顺序稳定排序。数值触发使用 Trigger 优先级、日期使用 EventDate 优先级。
- 实际队列继续逐个播放，新事件不打断当前事件。低优先级先已开始时，高优先级不能抢占。手动入口不绕过声明的地图/阶段约束。
- 等待资格、触发来源、入口和必要排序信息需入既有快照，按现有一次性规则去重；入候选/入队不代表完成。中断重试不能因 once 标记过早置位而永远无法再播。
- 当前阶段的事件未播完，不推进下一阶段；当前段内部续接先完成，不让无关插入事件混进收信中间。

MorningBeforeMap 每天执行一次，不在 S1 返回地图或每次关闭详情时重跑。AfterBusiness 每次实际经营结束边界检查，内容是否一次由事件配置决定；BeforeNight 同一次结束当天请求只运行一次。禁止同时由 HUD、DayFlow 和 NCS 各自推进日期。

本次至少用隔离逻辑测试数据覆盖一个 Cross 延后事件、一个 Hold 延后事件和多优先级事件。测试内容不混进正式故事配置。

### 3.4 地图红点接口与必做引导

地图红点表示“建筑里有玩家未看过的新行动”，不表示必做、不表示奖励可领。

- 新行动真正进入可展示集合时，为该行动可用实例生成/记录未看状态；建筑汇总任一未看行动即亮。
- 详情实际展示出某行动后标为已看。只是聚焦图标、详情被遮挡或尚未渲染不算看过。打开详情不自动执行行动。
- 看过后行动仍保留到完成/失效；同一实例消失再出现不反复亮点。新的每日实例或新的可用阶段实例可以再次提示，稳定按行动 ID 与实例版本判定，不能每次刷新都加版本。
- 初次进入某日时正常可见但未读的新增行动可以亮点；已完成/已失效/不可展示的行动不亮。红点允许在行动点不足但行动卡可见时显示，卡片按正常条件禁用。
- 已看实例入存档。旧存档缺状态时，当前可见的行动首次按未看处理；随后稳定。预览与沙盒不改变正式已看状态。
- 沿现有 MapPosition / extendedActions / 挂载行动和详情 UI 接入“内容变化通知、未看汇总查询、已展示确认”边界，不轮询 Excel，不加第二套行动定义。
- 可先用简单圆点/感叹号验证接口，正式美术以后替换。可在既有地图 Prefab 子节点挂显示组件，不另造全屏 Canvas、地图或输入系统。

S1 挂为 `cafe` 的必做行动，使用现有 `mustExecute` 和结束当天检查；不显示在事项面板。事项面板只列消耗行动点的活动，不能因为 mustExecute 自动把 S1 列进去。

结束当天被阻止时，不仅静默 return：沿现有地图聚焦接口聚焦/高亮首个未完成必做行动所在建筑，给出简短正常提示，例如“还有事情需要先处理。”不自动播放剧情；允许玩家继续其他可用活动。本次只有 S1 时定位咖啡馆。

### 5.2 正文顺序

以附录 B 为准，顺序为：夜里清扫与思考 → 猫叫 → 发现信图示 → 玩家警惕、拿扫帚、检查窗边 → 知觉条件心理活动 → 拿信阅读 → 密文信纸 → 返回对话解释解密 → 决定赴约 → 收好信、关门离开。

### 5.3 自动知觉条件段

到检查窗边的指定节点，读取现有玩家真实知觉，复用现有 NCS AbilityCheck / 条件判定与结果快照；只判一次。成功显示原文“窗台上并没有留下明显用力的痕迹……”一句，失败直接略过并汇入“事已至此，我拿起信，开始阅读”。没有失败台词、选择、掷骰、奖励或重新尝试按钮。

沿已接入的自动检定提示规范：成功首个正文框显示小字“知觉 ≥ 2 · 已察觉”，不占正文行、不额外点击；推进后清除，不重复显示。失败无提示。提示与正文使用同一个判定快照，预览属性值 1 和 2 要走真实条件逻辑，不让 UI 再独立判断。

### 5.4 通用读信入口

优先复用开场的信封、拆信图片、信纸和动画，抽取或扩展为通用读信能力。开场的取名、属性选择、署名确认仅属于开场，不进入 S2。复用后旧开场须回归，不能照搬其整条新游戏流程。

本次通用读信最小输入：来源定位、信封/信纸资源、标题/称呼、正文文本、完成与取消回调。名称和结构沿现有演出 DTO/配置风格；不新增 Excel 以外的独立剧本标准。Panel 只消费快照、不查 NCS 全局、不结算结果。

具体交互：

1. 原文指定的“一个信的图示出现在画面中央”先作为物件演出出现，此时仍读后面的警惕台词，不可提前点击进入读信。
2. 推进到“事已至此，我拿起信，开始阅读”完成后，暂停对话，在同一信封演出上启用拆信入口。左键、Enter/Space 均可拆信。
3. 展开信纸，显示“致新任店长：”和七行数字密文。数字顺序完整保留；按原文行段排版，窄屏允许按数字 token 边界折行，不拆两位数字、不省略。
4. 内容超出显示区时复用阅读分页/滚动能力，先读完整页再翻页；确认关闭只在已到最后页时可用。关闭动作显示清楚，例如“读完”。滚轮在信件中用于阅读，不同时推进下层对话。

## 9. 工程交付方式与完成标准

按顺序执行三包：

1. 入口和状态：测试跳转、阶段路由/日期时段约束、候选快照、必做引导、最小红点接口。
2. S1：正式配置、两场景演出、表情回退/点头/背景移动、完成后的正常经营入口回接。
3. S2：正式配置、自动知觉节点、通用读信复用、连续演出、夜晚回接及整章回归。

单包完成后报告该包验收，方便先试再修；不要将第一包完成写成整份 Spec 已完成。三包可以在同一工程任务中顺序推进，也可按包交接，不另开需要用户再次审批的设计回合。

最终交付报告至少包含：修改文件、配置/schema 增量、真实 ID/来源映射、全部占位及替换入口、生成与测试命令/结果、正式流程进入方法、尚未验证的项。应提供两条最短复现路径：“首日交接测试按钮 → S1 → 正常经营详情”和“S1 完成 → 结束当天 → S2 → 次日”。

禁止以“表已填”“硬编码预览能播”“GM 按钮出现”为完成标准。入口、正文、演出、条件、结果、地图回接和正式日程均须实际串通；正式美术可按上表明确占位，不影响逻辑完成判定。
