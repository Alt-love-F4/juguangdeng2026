# 咖啡馆新手教程：NCS 与模拟玩法协作 Spec

日期：2026-10-14。状态：本轮施工范围已获用户确认；本文定义 NCS 内容配置、首段玩法入口和交接接口，不包含后续咖啡制作玩法与蒙版的实现计划。

## 1. 目标

将《文案-新手教程.docx》的第一杯咖啡教程接入现有咖啡馆和 NCS。玩家由阿黛尔逐步讲解并亲手完成教学订单；NCS 负责叙事，咖啡模拟玩法负责真实交互和结果，聚焦蒙版由模拟玩法负责人实现。双方以可复核的步骤信号协作，不复制咖啡制作规则。

本轮的实际交付边界是：**完整整理并配置文案内容；玩法流程只做到玩家点击操作台并成功打开操作台。**操作台打开之后的制作步骤、蒙版、逐步解锁、真实操作完成判定、评分和奖励由咖啡玩法负责人后续施工。

## 2. 已确认的职责

| 范围 | 负责人 / 单一事实来源 |
|---|---|
| 阿黛尔、顾客的教程台词、叙事顺序和知觉条件分支 | NCS 叙事侧 |
| 订单、设备、杯子、原料、操作是否合法、制作结果、评分、金币及重做 | 现有咖啡模拟玩法 |
| 当前教学步骤、允许/等待的玩家操作及步骤完成判定 | 咖啡模拟玩法 |
| 高亮目标、遮罩、聚焦位置、操作引导动效 | 咖啡模拟玩法侧的教程表现组件 |
| 对话播放和对话结束回调 | 现有 Dialogue/NCS 演出链路 |
| 步骤之间的通知与稳定标识 | 两侧共用的教程协调接口；实施前与玩法负责人落实到现有架构 |

不得让 NCS 直接改杯子内容、订单、评分、金币或模拟玩法状态；不得由蒙版组件自行判定操作成功；不得另建咖啡配方或第二套教程剧情调度器。

本轮 NCS 侧必须交付：

- 用《文案-新手教程.docx》替换当前 `first_day_cafe` 中不属于原稿的临时/测试台词，保留原稿的剧情顺序和叙事信息。
- 配置完整的后续教程文本，包括顾客剧情、知觉成功/失败、点单、制作讲解、出餐反馈和结尾剧情；即使本轮玩法尚未接入，也必须有稳定的内容 ID，方便后续玩法 agent 逐段读取。
- 把“进入咖啡馆介绍完成 → 引导点击操作台 → 操作台成功打开”做成当前可运行的首段流程。
- 提供教程内容和步骤的读取说明、稳定 ID 规则、玩法侧完成信号约定，以及一个最小可用的接入示例。

本轮明确不交付：

- 研磨、烧水、冲泡、装杯、调浓度、调甜度、出餐等操作逻辑。
- 这些操作的蒙版、聚焦、输入锁定、完成判定和错误反馈。
- 评分、奖励、重做、烟花、音效和差评表现。
- 由 NCS 直接判断杯子或配方状态。

## 3. 教学流程基线

以下顺序以用户确认过的文案为内容基线。玩法侧可根据实际交互调整技术步骤，但任何删改叙事内容、条件和结果文案都需由内容负责人确认。

1. **进入咖啡馆：** 新局地图点击咖啡馆后进入现有 CoffeeShop 与其正式楼层/区域。保留现有 `CafeOpeningPanel` 和第一天 NCS 开场入口；将现有开场与文案“重新启航”段落对齐，避免同一段阿黛尔介绍重复播放。阿黛尔介绍大堂、操作间和楼层后，引导玩家点击操作台。
2. **第一位顾客：** 顾客 B 入店；播放老太太与阿黛尔的剧情。按玩家知觉值 `>= 3` 播放成功分支，否则播放失败分支；两支汇合后继续接单。分支由 NCS/既有数值和条件系统判断，模拟玩法不得自行复制知觉值。
3. **读懂订单：** 顾客点小杯、无糖黑咖啡。阿黛尔引导查看顾客和订单要求；订单数据仍由模拟玩法持有并显示。
4. **按步骤完成教学单：** 完整配置后续步骤的 NCS 文本和稳定 ID，但本轮只执行到操作台打开。操作台打开之后，玩法负责人接管步骤引导。后续设计仍遵循：阿黛尔先讲解当前步骤；模拟玩法开放/聚焦对应操作；真实操作完成后再请求下一段台词。
5. **可选操作演示：** 研磨、烧水、冲泡、装杯、基底、调浓度、甜度等可按文案提供选择性演示。跳过演示不得冒充完成实际制作；演示与实际操作状态的具体关系由玩法负责人确认。
6. **自由调配：** 完成指定教学单并结束首单教学步骤后，进入文案中的自由发挥阶段；不再由教程步骤阻止常规调配。是否立即解除所有蒙版和操作限制，应与玩法负责人确认并通过验收。
7. **交付与反馈：** 玩家出餐后，模拟玩法结算质量和奖励，并向叙事传递已结算的评价等级/结果。NCS 按结果播放顾客反馈；评价等级与奖金真实数值由模拟玩法计算，NCS 只消费结果，不重算。
8. **剧情收尾：** 按文案播放顾客离开、阿黛尔收尾、店长独白和黑场。教程退出后交还主循环。黑场后是否强制结束当天经营或返回常规自由经营，当前材料未明确，实施前必须由产品/DayFlow 负责人确认，不可由接入代码擅自推进日期。

评价文案基线为：独一无二、滴滴香浓、中庸之道、食不知味、好想退钱；文案含对应金币变化、差评重做和结算表现。实际等级阈值、奖励、惩罚、烟花/音效/表情等表现以咖啡模拟玩法和视觉负责人最终确认值为准。

## 4. 步骤与演出的协作契约

以下是职责契约，不预设接口必须叫某个类名或采用某种消息中间件。实施前先对照当前模拟玩法与 NCS 代码，选择最小的适配方式。

1. 咖啡馆教程开始时，主流程建立一个教程会话，并以稳定 ID 标记叙事段落/操作步骤；步骤 ID 不得依赖显示顺序或场景物体名称。
2. 对每个需要玩家操作的步骤，教程协调方请求 NCS 播放该步骤的配置台词。台词播放期间不应误判模拟操作已完成。
3. 台词结束后，模拟玩法激活当前操作步骤；蒙版/高亮表现订阅同一步骤 ID 与由玩法提供的焦点目标键。焦点目标缺失时应明确失败/诊断，不允许静默聚焦错误对象。
4. 只有模拟玩法依据真实领域状态确认操作完成，才发送对应步骤完成信号；NCS 收到信号后才播放下一段。重复、过期或非当前步骤的完成信号必须幂等忽略。
5. 教学订单完成时，模拟玩法先结算一次并发送稳定的结果分类/必要的表现信息；NCS 按结果播出顾客台词。金币和经营状态只结算一次。
6. 黑场、退出、切场景、读档或结束会话时，双方取消各自的演出、协程、订阅和延迟回调；旧回调不得推进新会话或旧步骤。
7. NCS 内容应通过项目已有配置和文本解析链路维护。若现有内容模型无法表达“播放一段、等待模拟信号、再继续”或条件分支，先在实现计划中指出缺口并提出最小扩展，禁止未经确认新增平行剧情框架。

**建议的逻辑握手：** 模拟侧请求一个台词段落 -> NCS 播放并回报台词结束 -> 模拟侧开放步骤/焦点 -> 玩家完成真实操作 -> 模拟侧回报步骤完成 -> NCS 继续。面向玩家的蒙版何时淡入/淡出属于表现侧，不得改变领域操作结果。

本轮真正启用的握手只到这里：

```text
地图点击咖啡馆
  -> NCS 播放首段咖啡馆介绍
  -> NCS/DayFlow 锁定非操作台交互
  -> 玩家点击操作台
  -> 玩法侧确认操作台已打开
  -> 发送 first_cafe_tutorial.workstation_opened
  -> 本轮交付结束，后续由玩法 agent 接管
```

后续步骤的配置可以提前存在，但在本轮不得因为“配置存在”而自动播放或假装玩法已完成。

## 5. 数据与配置边界

- 既有 NCS 表、文本 key、条件和 DialoguePanel 是叙事内容的首选来源；优先扩展现有表达能力。
- 教程步骤 ID、NCS 段落 ID、模拟焦点目标键使用稳定语义标识，并有明确映射；显示文本、美术物体名和层级路径不作为跨系统 ID。
- 顾客反馈按模拟玩法给出的评价等级映射到 NCS 文本；评价判定不放入 NCS。
- 本 spec 不要求改配方、制作表、玩家属性表或新增平行的咖啡制作数据。
- 原稿中的知觉分支、必经对话、玩家实际制作和评价反馈均应保留；若原稿内容与现有玩法事实冲突，先记录并由内容/玩法负责人共同决定，不静默删改。

## 6. 取消、恢复和兼容

- 教程不能被普通对话跳过、关闭或重复回调意外标记为完成；取消与完成必须是不同结果。
- 首单模拟状态和教程阶段恢复策略必须与现有咖啡馆存档、DayFlow 阶段协调，避免重复下单、重复奖励或恢复后 NCS 等待一个已丢失的步骤信号。
- 最小可接受策略是：退出/切场景时销毁旧教程会话并取消旧回调；恢复时由单一所有者根据存档的真实 DayFlow/模拟状态决定继续、重播当前叙事段落或回到可重试入口。
- 若第一版不支持教程中途存档，需由玩法负责人确认是否在教学阶段禁用存档，并在 UI/存档入口保持既有一致性；不能造成无提示的阶段丢失。
- 教程完成标记只服务首次引导与后续自由玩法，不重置或重复初始化 `PlayerRuntime`，不自动触发 NCS 事件结算两次。

## 7. 验收标准

- 从首日地图点击咖啡馆，只触发一份新手教程会话；正常旧档和第二天不会重播首日教程。
- 阿黛尔台词由 NCS 内容触发；知觉达标/未达标分支使用既有 NCS 数值条件，并在共同节点汇合。
- 每个实际操作步骤都满足“先讲解、后开放/聚焦、真实操作成功后再继续”；未完成、错误或重复信号不能让教程错误前进。
- 聚焦目标随当前步骤正确切换；NCS 不直接控制或实现蒙版视觉。
- 完成首单教学后进入文案要求的自由操作阶段；不会遗留阻挡输入的蒙版或步骤锁。
- 质量评价由模拟玩法结算一次，NCS 使用给定结果选择反馈文案；重做、奖励和惩罚不会重复结算。
- 退出、读档、切场景、取消和对话结束的异步回调不会串到另一教程会话。
- 黑场后的 DayFlow 去向、教程中途存档策略及可选演示的操作限制，在实现前已由负责人明确并纳入测试。
- 现有 `CafeOpeningPanel` / `first_day_cafe` 内容与教程文案的逐段对应已审阅，不存在重复或遗漏的开场段落。
- 本轮验收只要求玩家能从地图进入咖啡馆、看到首段 NCS、只能点击操作台并成功打开；后续制作玩法不计入本轮完成条件。

## 8. 职责与结果审查

叙事负责人审查台词、分支、条件与剧情节点；玩法负责人审查订单、交互步骤、焦点目标、操作约束、评分和资源结算。任何一侧不得代替另一侧改写其事实来源。

实现结果记录必须包括：

- NCS 表/文本 key、适配代码、玩法事件/步骤接口和蒙版代码各由谁修改。
- 实际使用的步骤 ID、焦点目标映射和结果等级映射。
- 测试场景/测试名、成功与失败路径、取消/恢复/重复事件的测试结果。
- 文案中未实现或为适配玩法而更改的逐项清单及负责人确认。
- 黑场后 DayFlow 去向、存档策略和可选演示限制的最终决定。
- 尚未完成的工作、已知问题和风险；不得只记录“已完成”。
