## 3. 必须遵守的产品规则

- 条件满足不等于立刻播放；事件要声明入口：Immediate、MorningBeforeMap、AfterBusiness、BeforeNight、MapAction。Immediate 也只在安全边界开始，不抢断当前对话。
- 日期用游戏年 670。10 月 6 日为相对 day=1，10 月 7 日为 day=2，以此按日历计算；日期相等、日期范围和数值跨越不是一回事。文件 S1/S2 后缀不自动代表上午/晚上，依据原文/时间线。
- 固定日期只限定发生时机，不无条件绕过分支与前置；终局/失败事件不能因为日期到了就全部自动播。
- 数值 Cross 保留实际跨越的资格，Hold 在入口重查当前条件，沿已定实现。不要把所有事件改成永久锁定，也不把所有事件强制改为日期触发。
- 地图型满足条件后展示该建筑行动；未看新行动使建筑亮点，实际展示后已看，完成/失效另算。必做与未看分开。
- 必做主线 0 AP、不列事项面板；未做完尝试结束当天时阻止并聚焦对应地点。非必做地图活动沿配置消耗 AP；不要凭空定 AP 成本。其他已配置地点仍可用。
- S1 已约定咖啡馆详情先只显示剧情，完成后返回地图聚焦咖啡馆，展开正常经营，由玩家点击；S2 在结束当天后、进入正常夜晚前自动播放。新事件照自己原文入口配置，不全部复制这一流程。
- 同人连续说话保持立绘，不重复入场；没写新表情就保持。换表情原位替换。旁白不清场，没立绘的人不找别的角色代演，不镜像右立绘。
- 只按原文指定配置场景、表情、CG、音效与动作。可声明缺资源占位，不新做美术，不凭空加华丽演出。S1 的 CG 说法已澄清只是切背景。
- 对话中可接阅读/信件/通知等现有演出，但需要准确续接位置和完成/取消语义。通用读信优先复用开场资源，不能调用开场取名/属性创建业务。
- 自动属性检定复用真实 NCS 属性与快照，按既有成功小字/失败不提示规范；主动选择或掷骰必须有原文依据。提示不替代原文分支。
- 仅完整完成才提交一次性结果。取消、预览、入队、看过详情不等于完成；预览不能修改正式状态、AP、存档、完成事实。
- 不擅自改变数值、奖励、关系、条件门槛、分支后果，不将缺数据硬填 0，不用自动成功绕过制作/品质/楼层/物品系统。小数成长与整数 API 冲突记为公共能力依赖，不自行缩放。

## 4. 内容标识、来源与跨窗口依赖

本轮新增根事件建议格式为 `<namespace>.<MMDD>.s<N>`，命名空间只用 neutral / rose / revolution / church。例如 `neutral.1013.s2` 与 `revolution.1013.s2` 是不同事件。页/行/结果在根 ID 下扩展；完成事实统一 `story.<rootEventId>.completed`。既有 oct07.s1 / oct07.s2 及已接入对象 ID 保持不改。若发现事件已存在，复用并记录实际映射，不重复发明。

每个事件登记“源目录 + 原文事件名 + 规范化游戏日期 + 新根 ID”。原稿编号只作别名，不跨派系直接查裸 ID。新玫瑰 `MA10.09-S1` 的命名差异保留原名并按时间线核实；两份 `MA70.10.13-S2` 绝不能撞 ID。

跨批次条件优先引用对方这套规范的已明确完成事实；更细的选项事实先查原文并给出拟议稳定 ID、值、写入事件和读取事件，写进本窗口依赖表，由总控合并。不能因为对方 Spec 未写好就自己创造一份重复内容；不能把无法消歧的旧编号强行映射到某分支。

正文无确切入口/成本但可安全作最小默认时，明确“工程默认”及依据；剧情身份、分支结果、金额、未完成文本等无法安全推定时写阻塞，不假装完整可施工。原文显式标未定/施工中必须保留。
