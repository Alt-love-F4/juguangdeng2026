# Android 手机适配设计

日期：2026-10-21
状态：待用户审核

## 目标

让现有项目能够构建 ARM64 Android 测试 APK，并可在横屏手机上完成启动、地图导航、咖啡馆经营和饮品制作。首版沿用当前 16:9 横屏 UI，不承诺竖屏重排。

Android 适配必须与 PC 输入和显示行为隔离。PC 保持现有鼠标/键盘操作、右键倾倒、地图滚轮缩放及对应教程提示，不因 Android 适配改变默认操作。

## 现状

- 项目使用 Unity 6.3、新 Input System、UGUI 和 InputSystemUIInputModule；当前正式 Build Settings 场景列表包含启动、咖啡馆和地图场景。
- 主 UI 按 1920x1080 横屏构图，部分 HUD 使用 2400x1350 CanvasScaler 参考分辨率；PlayerSettings 当前允许自动旋转至横竖屏。
- 普通 UGUI 点击和拖拽已有触摸兼容基础；咖啡馆 `FreeCafeRuntime` 的容器倾倒依赖 `Mouse.current.rightButton`，工作台教程也要求右键。`LatteArtPrototype`、地图缩放/平移部分逻辑直接读取 Mouse。
- 工作区已有 Android PlayerSettings 和纹理 `.meta` 未提交修改，必须在原值上审阅合并，不得重置或批量覆盖。
- 本机 Unity Editor 当前未安装 Android Build Support / SDK / NDK / OpenJDK，PATH 中也没有 ADB。因此代码与 Editor 测试可先完成；APK 构建和真机回归需要工具链可用。

## 平台隔离

1. 共用层只复用现有 UGUI 指针事件，不替换 EventSystem、不重写业务模型或存档。
2. Android 专用方向锁定、目标帧率、返回键、安全区和触屏手势通过 Android 平台入口/平台条件运行；不设置全平台运行时默认值，不更改 Standalone 图形、分辨率或输入设置。
3. PC 输入仍走原有鼠标/键盘分支。Android 条件逻辑之外不改变 PC 右键倾倒、左键拖放、地图滚轮/右键行为。
4. Android 教程根据平台显示触屏说明；PC 原教程文案、鼠标图示和提示触发条件保持不变。

## 手机交互

- **咖啡制作：**沿用单指拖放。对可倾倒容器，手指将容器拖到有效接收目标后短暂停留，再纵向拖动控制倾斜/流量；抬起手指结束倾倒。只在 Android 启用该识别，且只在有效目标上进入倾倒态，避免把普通移动误判为操作。取消、暂停、离开目标和中断触摸必须停止流体、释放输入所有权并按现有事务规则归还/保留容器。
- **PC 对照：**保留现有左键拖动加右键按住倾倒语义，不要求 PC 玩家学习新手势。
- **地图：**单指拖动平移、双指捏合缩放；PC 继续鼠标拖动、滚轮缩放和右键收起焦点。
- **拉花：**拉花表面改用平台无关的指针位置/按压状态；Android 单指绘制、抬指结束笔画，UI 命中仍阻止误绘。鼠标滚轮调笔刷保留在 PC；Android 拉花界面新增仅触屏显示的笔刷尺寸控件，不依赖滚轮，也不改变 PC 界面。
- **返回：**Android 系统返回键先复用当前顶层 UI 的取消/返回流程；不得绕开保存确认或直接清除进度。PC Escape 行为不变。
- **暂停/恢复：**应用失焦或切后台时终止临时触摸/拖拽和持续音效，不额外写入剧情事实或改变存档格式。

## 显示与性能

- Android 启动后锁定横屏；刘海、圆角和系统手势区域通过 `Screen.safeArea` 约束交互内容。
- 全屏背景和经营场景保持铺满屏幕；安全区只约束按钮、HUD、教程提示和可操作面板，不能整体缩小含全屏背景的根 Canvas。
- 继续使用现有 CanvasScaler 参考分辨率，在常见横屏比例下验证裁切、可触达性、文字溢出和拖拽命中；不批量改动所有 Prefab 的锚点。
- Android 默认帧率采用 60 FPS 上限；不改变 PC 帧率。首版不做未经设备测量的全局画质或资源压缩重设；保留现有 Android 纹理导入改动并审核冲突。

## Android 测试包

- Android 包名设置为稳定的反向域名 `com.altlovef4.juguangdeng2026`；使用 ARM64、IL2CPP 和 APK 输出，保留现有 Android SDK 版本及已配置的其他平台选项，除非 Unity 构建验证明确要求调整。
- 只包含当前正式 Build Settings 中的启动、咖啡馆、地图场景；不添加调试/叙事关系场景，不改变 PC 构建场景。
- 输出路径建议为 `Builds/Android/Spotlight-Android-Test.apk`，作为本地产物，不纳入功能源文件的提交。
- 先运行脚本编译与相关 EditMode/PlayMode 测试；Android Build Support 可用后构建 APK。若无连接设备/ADB，只能报告 APK 构建结果，不能宣称真机验收通过。

## 测试与验收

- 既有 PC 咖啡制作测试继续通过，特别是右键倾倒、抬起右键、普通左键拖放与容器归还行为。
- 为 Android 手势识别补充可在 Editor 运行的输入策略/状态机测试：有效目标限制、停留阈值、正反向倾斜、抬指结束、取消/失焦清理，以及非触屏策略仍映射到旧 PC 行为。
- 地图单指平移、双指缩放和 PC 滚轮缩放各有回归覆盖；拉花鼠标与触屏绘制都能生成笔画，UI 区域不绘制。
- 安全区测试覆盖全屏背景保持铺满、交互控件留在安全区，以及 16:9、19.5:9 等横屏比例。
- 检查 Android 包身份、ARM64/IL2CPP、场景列表和成功构建；真机试玩需确认启动、返回键、地图、教程、咖啡制作/倒液/拉花、切后台恢复和触控命中。
- PC 对照验收确认无 Android 条件逻辑运行、教程仍显示原鼠标说明，Standalone PlayerSettings 和现有设置面板行为不变。

## 非目标

- iOS 适配、竖屏 UI 重排、重新设计 PC 控制、联网/广告/商店接入。
- 重做咖啡馆场景、经营玩法、NCS 内容或存档结构。
- 为降低 APK 大小而批量重导入图片、覆盖现有纹理 `.meta` 或改变原始美术。
- 未经 Profiling 的全局画质降级。

## 已知风险与依赖

- Unity Android Build Support 未安装；Unity Hub/模块安装完成前无法在当前 Editor 生成 APK。
- 当前 PATH 中未发现 ADB，尚无法确认 Android 设备连接状态；构建后需确认 ADB/USB 调试环境和设备可用，再完成最终操作验收。
- 当前项目存在未提交工作区改动，尤其是 `ProjectSettings/ProjectSettings.asset` 和 Android 纹理导入 `.meta`；实施时必须逐项合并，不覆盖用户改动。
- 触屏倒液涉及现有拖放生命周期，必须先用小型输入策略/状态测试固定边界，再接入实时咖啡运行时，避免影响现有 PC 倾倒交易。
